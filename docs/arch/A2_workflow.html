節點分工（顏色 = 該用哪種實作）

  • 完整 Claude Code SDK/CLI（只剩 align_requirements——沒有獨立的 code_agent 節點）
  • 窄範圍 LLM + tool（plan_slices, test_agent, review_agent, synthesize_verdict）
  • 純 Python，不問 LLM（黑板狀態、合併、把關）
  • 人工（human_checkpoint，唯一需要人的地方）

跟 A（波次版）的關鍵差異

  • 沒有固定波次：slice 誰先做完就去認領下一個不衝突的任務
  • blackboard_dispatch 模擬多個外部獨立 CLI worker，真正的平行不是 LangGraph 的 Send 在管
  • 這份 sketch 沒辦法示範「worker 卡住問問題不擋別人」——真實部署下可以，單一 process 模擬做不到
